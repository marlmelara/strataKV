# Glossary additions

Terms that come up in the real code and are not already in the build spec's "Glossary" tab.
Each phase appends the terms it introduced.

## P0

| Term | Plain-English meaning | Where it shows up |
| --- | --- | --- |
| Advisory lock (`flock`) | A lock the OS records but does not enforce: it only works because every cooperating process asks first. Enough to stop two StrataKV processes opening one database; no defense against a process that never checks | `Env::LockFile`, the `LOCK` file |
| Compilation database | `compile_commands.json`, a list of every source file and the exact flags used to compile it. Tools like clang-tidy need it to analyze code the same way the compiler saw it | Generated by CMake, used by the CI lint job |
| File descriptor | The small integer the OS gives you to refer to an open file. Python exposes it as `f.fileno()` | `fd_` in `PosixWritableFile` |
| `FetchContent` | A CMake feature that downloads a dependency's source at configure time and builds it as part of your project. Avoids a vendored copy or a git submodule to keep in sync | How GoogleTest arrives |
| fsyncgate | The 2018 discovery that on Linux a failed `fsync` may leave the kernel having already dropped the dirty pages and cleared the error, so a retry reports success while the data is gone. Postgres now treats `fsync` failure as fatal | Why `PosixWritableFile` makes a sync failure sticky |
| Known-answer test | A test that checks an algorithm against a published, externally agreed-upon output rather than against whatever the code currently does. The only kind of test that can catch a checksum implementation being self-consistently wrong | `Crc32c.MatchesKnownAnswers` |
| Out-of-source build | Keeping all compiler output in a separate directory (`build/`) instead of beside the sources, so several configurations can coexist and the tree can be wiped by deleting one folder | One directory per preset: `build/debug`, `build/asan`, ... |
| Page cache | The OS's in-memory copy of recently used file contents. A plain `write` only reaches here; `fsync` is what pushes it onward to the drive | Why `Append` returning OK does not mean "durable" |
| Position-independent code (PIC) | Machine code that works regardless of where in memory it is loaded. Required for anything linked into a shared library, which is what a Python extension module is | `POSITION_INDEPENDENT_CODE ON` on the engine library |
| scikit-build-core | The Python build backend that makes `pip install .` run CMake and place the compiled `.so` inside the Python package | `pyproject.toml`, `[tool.scikit-build]` |
| Short write | When `write()` accepts fewer bytes than you asked for, which is legal and must be looped over. Ignoring it silently truncates data | `WriteFully` in `src/env.cc` |
| Translation unit | One `.cc` file plus everything it includes — the unit the compiler actually processes. Explains why a header included twice would be an error without `#pragma once` | Every `.cc` in `src/` |

## P1

| Term | Plain-English meaning | Where it shows up |
| --- | --- | --- |
| Acquire load | A read of an atomic that also guarantees you see everything the writer wrote before its release store | `FindGreaterOrEqual` |
| Arena (bump allocator) | Hands out pieces of big blocks by advancing a cursor, and frees every block at once. No individual frees, which is what makes lock-free reads safe | `src/arena.h` |
| Internal key | A user key plus an 8-byte trailer of sequence number and type. What is actually stored and sorted | `src/internal_key.h` |
| Placement new | Constructing an object in memory you already own, instead of allocating | `SkipList::NewNode` |
| Publication | The single release store that makes a fully built node reachable by readers | `SkipList::Insert` |
| Release store | A write to an atomic that publishes everything written before it to any acquire load that sees the value | `SkipList::Insert` |
| Sequence number | A monotonically increasing counter stamped on every operation. It is what "newer" means, and what a snapshot is measured against | Assigned in `DBImpl::Write` |
| Snapshot | A sequence number a read is pinned to, so writes newer than it stay invisible | `DBImpl::Get` |
| Torn record | A WAL record only partly written when the process died. Normal after a crash, never an error, because it was never acknowledged | `WalReader::Replay` |
| Trailer | The 8 bytes appended to every user key: 7 of sequence number, 1 of type | `PackSequenceAndType` |
| WriteBatch | A group of operations that becomes one WAL record with one checksum, so it replays entirely or not at all | `include/stratakv/write_batch.h` |

## P2

| Term | Plain-English meaning | Where it shows up |
| --- | --- | --- |
| Background flush | Writing a full memtable out to an SSTable on a separate thread, so writers are not blocked by disk I/O | `DBImpl::BackgroundLoop` |
| Data block | A ~4 KB run of sorted entries inside an SSTable; the unit a lookup reads | `SSTableBuilder::FlushDataBlock` |
| Double hashing | Deriving all k bloom probes from one hash by repeatedly adding a rotation of it, instead of computing k hashes | `BloomBuilder::Finish` |
| False positive | A bloom filter saying "maybe here" for a key that is absent. Costs one wasted disk read, never a wrong answer | `BloomFilter::MayContain` |
| Filter block | The encoded bloom filter stored inside an SSTable, plus its probe count | `SSTableBuilder::Finish` |
| Footer | The fixed-size trailer of an SSTable holding the filter and index locations, a magic number, and a checksum. Being last and fixed-size is what lets a reader find everything with one read | `kFooterSize` |
| Immutable memtable | A full memtable set aside for flushing while a fresh one takes writes. Still readable, never written to again | `DBImpl::imm_` |
| Index block | One entry per data block, holding that block's last key, so a binary search finds the single block that could hold a key | `SSTableReader::Open` |
| L0 | The level holding freshly flushed SSTables. Files here overlap in key range, since each is whatever keys happened to be written, so only recency orders them | `DBImpl::l0_` |
| Magic number | A fixed constant stored in a file so a reader can tell it is the right kind of file at all | `kTableMagic` |
| Probe | One bit position a bloom filter checks. More probes per key means more evidence, up to a point | `BloomFilter::probes` |
| Rotation | Retiring a full memtable, starting a new log and memtable, and handing the old one to the flush thread | `DBImpl::MakeRoomForWrite` |
| Sequence watermark | A zero-operation record at the start of each new log, carrying the current sequence number so numbering survives having every log flushed and deleted | `DBImpl::WriteSequenceWatermark` |
| SSTable | A sorted, immutable file of entries with its own filter, index, and footer. Never modified after it is written, which is what makes crash safety tractable | `src/sstable_builder.h` |

## P3

| Term | Plain-English meaning | Where it shows up |
| --- | --- | --- |
| Compaction input / output | The files a compaction reads, and the fresh files it writes. Inputs are deleted once the outputs are recorded | `CompactLevel0` |
| CURRENT | A tiny file naming the live MANIFEST, replaced atomically by write-sync-rename-sync | `SetCurrentFile` |
| MANIFEST | An append-only log of changes to the file set. Authoritative: it, not the directory listing, says what the database consists of | `VersionSet::LogAndApply` |
| MVCC (multi-version concurrency control) | Readers see a fixed version of the data while writers carry on. Here it is a Version snapshot plus a sequence number | `DBImpl::Get` |
| Read amplification | How many files a single lookup may have to consult. Compaction reduces it by collapsing L0 into non-overlapping L1 files | `Version::Get` |
| Smallest snapshot | The oldest sequence number any in-flight read might still need. Compaction may not drop a version at or above it | `DBImpl::SmallestActiveSnapshot` |
| Space amplification | Bytes on disk divided by bytes of live data. Measured at 1.44x after compaction | [NUMBERS.md](NUMBERS.md) |
| Version | An immutable snapshot of the file set, reference counted. Holding one guarantees its files stay open and undeleted | `src/version.h` |
| Version edit | One recorded change to the file set: files added, files removed, counters updated | `VersionEdit` |
| Write amplification | Bytes written to disk per byte the user wrote. Compaction spends it to buy back read and space amplification | `CompactLevel0` |

## P4

| Term | Plain-English meaning | Where it shows up |
| --- | --- | --- |
| Fault injection | Making an operation fail on demand, so error-handling code can actually be executed by a test rather than merely reviewed | `Env::SetFailureInjectionForTesting` |
| Group commit | Merging several writers' batches into one log record with a single shared `fsync`. Measured 4.7x faster at 8 writers | `DBImpl::BuildBatchGroup` |
| Leader / follower | The writer at the front of the queue does the log append and the `fsync` for everyone it merges; the others sleep and collect its result | `DBImpl::Write` |
| Thundering herd | Waking many threads for an event only one can act on, so nearly all immediately sleep again. Avoided by giving each writer its own condition variable | `Writer::cv` |
| Throughput | Operations completed per second. The number group commit exists to raise, as opposed to latency, which it slightly raises for the leader | [NUMBERS.md](NUMBERS.md) |
